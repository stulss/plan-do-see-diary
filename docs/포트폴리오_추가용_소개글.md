# 포트폴리오 추가용 소개글

> 구현·배포 후 괄호 안 수치와 주소를 채운다. 채우기 전에는 포트폴리오에 올리지 않는다.

## 한 줄 소개

계획을 세우고, 실제로 한 일을 기록하고, 둘의 차이를 되짚어 다음 계획으로 되돌리는 개인 다이어리 웹 앱.

## 소개글 (3~4문장)

할 일에 체크만 하고 끝나는 도구가 아니라, 내가 계획을 어느 쪽으로 자주 틀리는지 눈으로 보게 만드는 도구를 만들었다.
계획의 예상 시간과 실제 실행 기록을 각각 다른 표에 저장해 실행 기록이 원래 계획을 덮어쓰지 않게 했고,
돌아보기 화면의 집계 숫자를 누르면 그 숫자가 나온 근거 기록 목록으로 바로 이동한다.
완료 중복은 버튼 잠금이 아니라 데이터베이스 기본키 제약으로 막아, 완료 버튼을 연타해도 기록과 집계가 각각 한 번만 늘어난다.

## 기술적으로 신경 쓴 점

- **집계와 목록의 조건을 한 곳에서 생성** — 숫자와 근거 기록이 어긋나지 않도록 조건 생성 함수를 공유
- **시간대·단위 규칙 고정** — 마감일은 서울 날짜, 시각은 UTC 저장 후 서울 표시, 시간 단위는 전 구간 '분'
- **이력 보존을 DB 트리거로** — 계획을 고쳐도 고치기 전 값이 자동으로 남음
- **비밀값 분리** — DB 접속 문자열은 서버 라우트에서만 사용, 클라이언트에 노출 없음
