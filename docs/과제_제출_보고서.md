## 1. 프로젝트 개요

플랜두씨 다이어리는 계획(Plan), 실제 실행(Do), 돌아보기(See)를 하나의 데이터 흐름으로 연결하는 개인 플래너다. 사용자는 계획의 기간·우선순위·성공 기준·예상 시간을 정하고, 계획에 연결된 할 일과 실제 실행 기록을 남긴다. 돌아보기 화면은 계획 수, 완료 수, 지연 수, 막힘 수, 예상 시간, 실제 시간과 차이를 계산하며, 각 숫자를 누르면 같은 조건으로 만든 근거 목록으로 이동한다.

## 2. 완성 범위

P0부터 P7까지 모두 완료했다. Next.js App Router 프로젝트와 Vercel Marketplace Supabase를 연결하고, 표 6개·계획 수정 트리거·완료 중복 방지 제약을 적용했다. 계획·할 일·실행 기록·돌아보기·JSON 내보내기 API와 일간·주간·월간 플래너를 구현했다. 사용자가 실제 계획과 할 일 5건, 실행 기록 3건을 직접 입력했으며, 검증 후 GitHub와 Vercel에 공개 배포했다.

## 3. 시스템 구조와 데이터 규칙

브라우저는 Next.js 서버 라우트만 호출하고 데이터베이스 접속 문자열은 서버 환경변수에만 둔다. 서버는 관리형 PostgreSQL에 원시 SQL로 접근한다. `plan`, `plan_revision`, `task`, `task_completion`, `run_log`, `review`의 6개 표를 사용한다.

- 모든 소요 시간은 분 단위로 저장·계산·표시한다.
- 계획 기간과 마감일은 서울 날짜 `date`, 시각은 `timestamptz`로 UTC 저장 후 서울 시간으로 표시한다.
- 할 일 삭제는 `deleted_at` 소프트 삭제이며 집계는 삭제되지 않은 행만 사용한다.
- 완료는 `task_completion.task_id` 기본키와 `ON CONFLICT DO NOTHING`으로 중복을 막는다.
- 계획 수정 전 값은 애플리케이션이 아니라 DB 트리거가 `plan_revision`에 남긴다.
- 실행 기록은 별도 표에 저장하여 계획·할 일의 예상 시간을 바꾸지 않는다.

## 4. 사용자 경험

첫 화면은 일간·주간·월간 플래너다. 선택한 날짜를 기준으로 기간 요약, 진행 계획, 할 일, 예상·실제 시간을 한눈에 볼 수 있다. 플래너 안에서 새 계획과 새 할 일을 바로 추가할 수 있다. 계획 상세는 수정 이력을, 할 일 상세는 완료 상태와 실행 기록을 보여준다. 돌아보기는 숫자와 근거 목록을 연결하고, 고칠 점 한 줄을 다음 계획으로 이월한다.

## 5. 요구사항별 핵심 증거

- 카드 1(C04~C08): 계획 기간·우선순위·예상 시간과 계획 수정 이력 화면
- 카드 2(C09~C22): 할 일 5건, 검색·거르기·정렬, 완료·되돌리기와 완료 중복 방지
- 카드 3(C23~C27): 시작·종료 시각, 실제 시간, 막힌 이유가 할 일에 연결된 실행 기록
- 카드 4(C28~C33, C83): 계획 5·완료 1·지연 4·막힘 3·예상 200분·실제 38분과 근거 목록 1건
- 카드 5(C34~C82): 실제 Supabase 저장, 새로고침 복원, JSON 내보내기, 공개 안내, 비밀값 비노출, 스크립트 문자 안전 표시

완료 1건 화면은 중복 방지 검증 중 캡처했으며 검증 후 완료 기록은 원래 0건으로 되돌렸다. 스크립트 모양 문자열도 글자 그대로 표시되는 장면을 캡처한 뒤 원래 메모로 복원했다.

## 7. 문제 해결

초기 Next.js 버전의 보안 취약점은 16.3.3으로 올려 해결했다. Supabase 무료 연결 풀에서 JSON 내보내기를 병렬 조회하면 약 30초가 걸리는 문제는 6개 조회를 순차 실행해 약 0.4초로 줄였다. 트랜잭션 풀러에서 prepared statement가 사라지는 간헐 오류는 Postgres.js에 `prepare: false`를 적용해 해결했다.

## 8. AI와 사용자 판단

AI에게는 요구사항 분석, 데이터베이스·API·플래너 화면 구현, 자동 검사와 문서 정리를 맡겼다. 사용자는 Vercel에서 Supabase 데이터베이스를 만들고 연결했으며 실제 계획·할 일·실행 기록의 내용을 직접 정해 입력했다. 또한 계획과 할 일을 별도 화면에서만 입력하는 초기 흐름을 따르지 않고, 플래너 화면에서도 바로 추가할 수 있도록 수정을 요청했다.

## 9. 제출 정보와 30초 확인

결과물 주소를 로그인 없이 열고, 할 일 완료 버튼을 연속으로 누른 뒤 돌아보기의 완료 수를 클릭한다. 완료 수가 한 번만 증가하고, 같은 기간의 완료 근거 목록 건수가 숫자와 일치하면 통과다. `/api/export`에서는 실제 자료가 JSON 파일 하나로 내려받아져야 한다.

## 10. 결론

플랜두씨 다이어리는 계획을 입력하는 데서 끝나지 않고 실제 실행과 차이를 기록하고, 그 근거를 확인하며, 다음 계획으로 개선점을 되돌리는 순환 구조를 완성했다. 핵심 규칙을 데이터베이스 제약·트리거·공유 조건 함수로 보장했고, 실제 자료·자동 검사·브라우저 검증·공개 배포와 증거자료까지 확보했다.
