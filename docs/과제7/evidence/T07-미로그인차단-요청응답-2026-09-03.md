# 미로그인 차단·문구 동일성 요청·응답 원문 (2026-09-03)

대상: 공개 배포 `https://plan-do-see-diary.vercel.app`
방법: `curl` — **쿠키를 붙이지 않은 요청**과, 일부러 틀린 값을 넣은 요청만 보냈다.
**실제 비밀번호는 사용하지 않았고 계정을 만들지 않았다.** 모든 요청은 거절되는 것이 정상이다.

---

## 1. 로그인하지 않으면 자료 API 가 열리지 않는다 (T07-C124)

```http
GET /api/tasks HTTP/2
Host: plan-do-see-diary.vercel.app
(쿠키 없음)

HTTP 401
{"error":"로그인이 필요합니다."}
```

## 2. 로그인하지 않고 자료 화면 주소를 열면 로그인 화면이 나온다 (T07-C97 / C03)

```http
GET /tasks HTTP/2
Host: plan-do-see-diary.vercel.app
(쿠키 없음)

HTTP/2 307
location: /login
content-type: text/plain
server: Vercel
date: Thu, 03 Sep 2026 04:55:09 GMT

Redirecting
```

자료 대신 `/login` 으로 보내진다.

## 3. 내보내기도 로그인 없이는 열리지 않는다 (T07-C133 의 반대 방향)

```http
GET /api/export HTTP/2
(쿠키 없음)

HTTP 401
{"error":"로그인이 필요합니다."}
```

---

## 4. 아이디가 없을 때와 비밀번호만 틀렸을 때의 안내가 같다 (T07-C99)

**같은 주소·같은 방식이고, 달라진 것은 아이디가 존재하는지 하나뿐이다.**

### 4-1. 없는 아이디

```http
POST /api/auth/login HTTP/2
Content-Type: application/json
{"login_id":"nosuchuser_zzz","password":"(틀린 값)"}

HTTP 401
{"error":"아이디 또는 비밀번호가 올바르지 않습니다."}
```

### 4-2. 있는 아이디 + 틀린 비밀번호

```http
POST /api/auth/login HTTP/2
Content-Type: application/json
{"login_id":"test","password":"(틀린 값)"}

HTTP 401
{"error":"아이디 또는 비밀번호가 올바르지 않습니다."}
```

**상태코드 401 과 문구가 글자까지 완전히 같다.** 응답만 보고는 그 아이디가 있는지 알 수 없다.

---

## 5. 같은 아이디로 두 번 가입되지 않는다 (T07-C98)

```http
POST /api/auth/signup HTTP/2
Content-Type: application/json
{"login_id":"test","nickname":"zzdup","email":"dup_zz@example.com","password":"(규칙을 만족하는 값)"}

HTTP 409
{"error":"이미 사용 중인 아이디입니다."}
```

화면의 중복확인을 건너뛰고 바로 제출해도 **DB 유니크 인덱스가 막는다.**

## 6. 비밀번호 규칙을 못 채우면 가입되지 않는다

대문자가 빠진 값으로 시도했다.

```http
POST /api/auth/signup HTTP/2
Content-Type: application/json
{"login_id":"zzcheck01","nickname":"zzcheck01","email":"zz01@example.com","password":"(대문자 없는 값)"}

HTTP 400
{"error":"비밀번호는 10자 이상이며 대문자·소문자·숫자·특수문자를 각각 1자 이상 포함해야 합니다."}
```

## 7. 중복확인은 사용 가능 여부만 알려 준다

```http
POST /api/auth/check HTTP/2
Content-Type: application/json
{"field":"login_id","value":"test"}

HTTP 200
{"available":false}
```

이메일·닉네임 등 **다른 정보가 함께 돌아오지 않는다.** 이 경로로는 이메일 존재 여부를 확인해 주지 않는다.

---

## 이 기록으로 확인되지 않는 것

로그인한 세션이 있어야 하는 확인은 여기에 없다. 아래는 사용자가 직접 로그인해 촬영해야 한다.

- 같은 주소·같은 방식의 **성공 응답**(로그인 상태 `GET /api/tasks` → 200)
- 로그아웃 뒤 **같은 쿠키 값**으로 다시 요청 → 401 (T07-C109 / C110 / C114)
- 남의 자료 **양방향** 읽기·수정·삭제 → 404 (T07-C117 ~ C120)
- 목록 응답에 남의 자료가 섞이지 않음 (T07-C125)
- 거절 앞뒤 상대 계정 자료 건수 대조 (T07-C122)
