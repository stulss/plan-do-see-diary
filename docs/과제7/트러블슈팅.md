# 트러블슈팅 — 잠긴 플랜두씨 다이어리

> 실제로 겪은 문제만 적는다. 겪지 않은 문제를 미리 적어 두지 않는다.
> 형식: **문제 → 시도한 것 → 비교 → 해결 → 배운 점**

## 기록

### 1. 인증 스키마 적용이 DB 락을 기다리며 끝나지 않음

- **문제**: `schema_auth.sql` 실행을 연속으로 시작한 두 Node 프로세스가 관리형 PostgreSQL의 DDL 락을 기다리며 끝나지 않았다.
- **시도**: 실행 중인 명령을 확인해 해당 마이그레이션 프로세스 두 개만 종료하고, PostgreSQL 트랜잭션 롤백 뒤 인증 표·소유자 컬럼 상태를 다시 검사했다.
- **비교**: 무기한 기다리는 방식과 연결·락 제한 시간을 두고 실패 시 전체 롤백하는 방식을 비교했다.
- **해결**: `scripts/apply-auth-expand.mjs`에서 무료 풀러 조회를 순차 실행하고 `connect_timeout=15초`, `lock_timeout=10초`, `statement_timeout=60초`를 적용했다. 한 번만 재실행해 전체 DDL을 한 트랜잭션으로 적용했다.
- **배운 점**: DDL 마이그레이션은 중복 실행을 막고, 적용 상태 사전 검사와 락 제한 시간을 둔 뒤 한 프로세스만 실행한다.

### 2. DB 시간대를 바꿨지만 풀러 연결에서 UTC가 계속 보임

- **문제**: `ALTER DATABASE ... SET timezone`은 성공했지만 Supabase 풀러가 기존 물리 연결을 재사용해 새 앱 연결에서 UTC가 보였다.
- **해결**: DB 기본값 변경·검증은 `POSTGRES_URL_NON_POOLING` 직접 연결로 수행하고, 앱의 공용 연결에는 `TimeZone: "Asia/Seoul"`을 명시했다.
- **배운 점**: DB 기본 설정과 연결 풀의 세션 설정은 별개로 검증해야 하며 `timestamptz` 값 자체에 9시간을 더하면 안 된다.

### 3. 계획 ID 기반 색상에서 서로 다른 계획이 같은 색이 됨

- **문제**: 계획 ID를 8로 나눈 나머지로 색을 정하자 ID 간격이 8인 계획끼리 색이 겹쳤다.
- **해결**: 현재 계획 목록 순서로 팔레트를 배정해 최대 8개까지 서로 다른 색을 보장하고, 같은 목록을 할 일 색상에도 공유했다.
- **배운 점**: 제한된 팔레트는 식별자 해시보다 현재 표시 집합 안의 충돌 방지가 우선이다.

### 4. 날짜 입력의 제목 영역까지 달력 클릭 범위가 넓어짐

- **문제**: `<label>`이 날짜 입력을 감싸고 있어 제목을 눌러 발생한 합성 클릭도 `showPicker()`를 실행했다.
- **해결**: 포인터가 실제 입력 박스에서 시작한 경우만 달력을 열도록 제한했다.
- **배운 점**: 접근성용 label 활성화 범위와 사용자에게 보이는 컨트롤 경계가 다를 수 있으므로 실제 hit area를 확인해야 한다.

## 미리 알아 둔 함정 (겪으면 위 형식으로 옮겨 적는다)

| 예상 함정 | 먼저 볼 곳 |
|---|---|
| 로그아웃했는데 예전 쿠키로 계속 들어와진다 | 서버에서 `user_session` 행을 정말 지웠는지 → 쿠키만 지우고 있지는 않은지 → 만료 시각을 확인하고 있는지 |
| 한 건 조회는 막혔는데 **목록**에 남의 자료가 섞인다 | `lib/domain/query.ts` 의 `buildTaskWhere()` 에 소유자 조건이 들어갔는지 → 목록과 한 건 조회가 서로 다른 코드 경로인지 → 응답 전체를 열어 남의 ID 가 하나도 없는지 |
| 거절은 되는데 상대 자료가 조금 바뀌어 있다 | 주인 확인 전에 저장부터 하고 있지 않은지 → `UPDATE … WHERE id=$1 AND user_id=$2` 형태인지 → 거절 전후 건수를 세어 비교 |
| 같은 비밀번호인데 저장값이 똑같이 나온다 | 계정마다 다른 소금값을 쓰는지 → 고른 방법이 소금값을 자동으로 붙이는지 → 단순 해시 한 번으로 끝내고 있지 않은지 |
| 로컬은 되는데 배포하면 로그인이 안 된다 | 쿠키 `Secure` 속성과 HTTPS → 배포 환경변수 `DATABASE_URL` 등록 여부 → Production Branch 가 `main` 인지 |
| 무료 DB 가 쉬었다 깨어나며 첫 요청이 느리다 | 과제 6에서도 관찰된 현상. 재현 시각과 소요 시간을 기록 |
