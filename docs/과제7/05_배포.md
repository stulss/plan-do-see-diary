# 05. 배포 — 잠긴 플랜두씨 다이어리

## 1. 배포처 선택

| 후보 | 장점 | 단점 | 결정 |
|---|---|---|---|
| **Vercel** | 과제 6에서 이미 쓰고 있어 설정·계정이 그대로다. Next.js 를 만든 곳이라 App Router·미들웨어가 그대로 동작한다 | 무료 등급은 상용 사용에 제한이 있다 | **선택** |
| Netlify | 무료 등급이 넉넉하다 | Next.js 미들웨어·서버 라우트가 어댑터를 거쳐 동작해 과제 6과 동작 차이가 생길 수 있다 | 기각 |
| Cloudflare Pages | 빠르다 | 워커 런타임이라 `bcryptjs` 와 Node 전용 API 사용에 제약이 생길 수 있다 | 기각 |
| 직접 서버(VM) | 자유롭다 | 서버 관리·HTTPS 인증서·비용이 과제 범위를 넘는다 | 기각 |

**고른 이유 한 문장**: 과제 6과 같은 곳에 올려야 무엇이 달라졌는지가 인증 때문임이 분명해지고, 배포 환경 차이로 인한 변수를 없앨 수 있어서.

## 2. 배포 전 준비

| 항목 | 값 |
|---|---|
| 브랜치 | `plan-do-see-diary_to7` (Production Branch 로 지정) |
| DB | **과제 6과 같은 DB 를 공유한다.** 새로 만들지 않는다 |
| 쿠키 | 운영에서는 `Secure` 가 켜져야 하므로 HTTPS 필수 |

### 환경변수 (전부 서버 전용, `NEXT_PUBLIC_` 접두어 금지)

| 이름 | 용도 |
|---|---|
| `DATABASE_URL` | 과제 6과 공유하는 DB 접속 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | 구글 OIDC |
| `KAKAO_CLIENT_ID` / `KAKAO_CLIENT_SECRET` | 카카오 OIDC |

값은 어떤 문서에도 적지 않는다. 로컬은 `.env.local`(`.gitignore` 대상), 배포는 Vercel 환경변수에만 둔다.

### 소셜 제공자 사전 등록

| 제공자 | 할 일 |
|---|---|
| 구글 | Google Cloud Console 에서 OAuth 클라이언트 생성 → 승인된 리디렉션 URI 등록 |
| 카카오 | 카카오 디벨로퍼스 앱 생성 → **카카오 로그인 > OpenID Connect 활성화** → Redirect URI 등록 → Client Secret 발급 |

**Redirect URI 는 로컬과 배포 두 벌을 모두 등록한다.**

```
http://localhost:3000/api/auth/oauth/google/callback
http://localhost:3000/api/auth/oauth/kakao/callback
https://(배포주소)/api/auth/oauth/google/callback
https://(배포주소)/api/auth/oauth/kakao/callback
```

> **카카오 이메일**: `account_email` 동의항목은 비즈 앱 전환 + 비즈니스 정보 심사(영업일 3~5일)를 거쳐야 쓸 수 있다.
> 심사 전에는 이메일 없이 계정이 만들어지며, 이는 설명서 6항에 한계로 적는다.

## 3. 절차

1. Vercel 에서 **새 프로젝트**를 만들고 저장소 `stulss/plan-do-see-diary` 를 연결한다.
2. Production Branch 를 **`plan-do-see-diary_to7`** 로 지정한다. (`main` 으로 두면 과제 6 코드가 올라간다.)
3. 공유 DB 에 `schema_auth.sql` 을 적용한다. **소유자 컬럼은 반드시 4단계 순서로**(기획 4-3): NULL 허용 추가 → 기존 행 UPDATE → 임시 DEFAULT → NOT NULL.
4. 환경변수 5개를 등록한다.
5. 배포 후 **새 시크릿 창**에서 결과물 주소를 연다.
6. 첫 화면이 로그인 화면인지, 로그인 없이 `/tasks` 를 열면 로그인 화면이 나오는지 확인한다.
7. 새 계정을 하나 만들어 **빈 다이어리**가 나오는지 확인한다(내 기록이 보이면 안 된다).
8. 구글·카카오 로그인을 각각 한 번씩 눌러 콜백이 정상 동작하는지 확인한다.

## 4. 배포 후 — PR 병합

배포와 검증이 끝나면 **미루지 말고** `plan-do-see-diary_to7` → `main` PR 을 병합한다.
병합 전까지는 과제 6 배포가 같은 DB 를 인증 없이 보여 주기 때문이다.

병합 직후 임시 DEFAULT 를 제거한다:

```sql
ALTER TABLE plan   ALTER COLUMN user_id DROP DEFAULT;
ALTER TABLE task   ALTER COLUMN user_id DROP DEFAULT;
ALTER TABLE review ALTER COLUMN user_id DROP DEFAULT;
```
