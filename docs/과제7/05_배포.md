# 05. 배포 — 잠긴 플랜두씨 다이어리 (과제 7)

과제 6 배포 문서는 `docs/05_배포.md` 에 그대로 남아 있다. 이 문서는 인증판 배포만 다룬다.

## 1. 배포처

과제 6과 **같은 Vercel 프로젝트에 그대로 이어서 배포**한다. 같은 곳에 올려야 무엇이 달라졌는지가 인증 때문임이 분명해지고, 배포 환경 차이로 인한 변수가 없다.

| 후보 | 장점 | 단점 | 결정 |
|---|---|---|---|
| **Vercel (과제 6과 동일)** | 설정·환경변수·도메인이 그대로다. Next.js 를 만든 곳이라 App Router·미들웨어가 그대로 동작한다 | 무료 등급은 상용 사용에 제한이 있다 | **선택** |
| Netlify | 무료 등급이 넉넉하다 | 미들웨어·서버 라우트가 어댑터를 거쳐 동작해 과제 6과 동작 차이가 생길 수 있다 | 기각 |
| Cloudflare Pages | 빠르다 | 워커 런타임이라 `bcryptjs` 와 Node 전용 API 사용에 제약이 생길 수 있다 | 기각 |
| 직접 서버(VM) | 자유롭다 | 서버 관리·HTTPS 인증서·비용이 과제 범위를 넘는다 | 기각 |

## 2. 배포 전 준비

| 항목 | 값 |
|---|---|
| 브랜치 | `main` |
| DB | **과제 6과 같은 인스턴스.** 새로 만들지 않는다 |
| 쿠키 | 운영에서는 `Secure` 가 켜지므로 HTTPS 필수 |

### 환경변수

| 이름 | 용도 |
|---|---|
| `DATABASE_URL` | DB 접속 (서버 전용) |

**과제 6에서 쓰던 그대로이며 새로 추가할 값이 없다.** 세션 토큰을 서명하지 않으므로 서명키가 필요 없다.
`NEXT_PUBLIC_` 접두어는 어떤 값에도 붙이지 않는다. 붙이면 브라우저 번들에 들어간다.

## 3. 배포 순서

**DB 마이그레이션을 먼저 적용해야 한다.** 순서를 지키지 않으면 인증판 배포 전까지 과제 6 앱의 등록 기능이 깨진다.

1. `schema_auth.sql` 의 표 생성과 1단계(소유자 컬럼 NULL 허용 추가)를 적용한다.
2. `npm run dev` 로 띄우고 `/signup` 에서 소유자 계정을 만든다.
3. 그 계정 id 로 2~4단계를 적용한다: 기존 자료 `UPDATE` → 임시 `DEFAULT` → `NOT NULL`.
4. `git push` 로 `main` 을 올려 Vercel 이 배포하게 한다.
5. 배포가 끝나면 **임시 `DEFAULT` 를 제거한다.**

```sql
ALTER TABLE plan   ALTER COLUMN user_id DROP DEFAULT;
ALTER TABLE task   ALTER COLUMN user_id DROP DEFAULT;
ALTER TABLE review ALTER COLUMN user_id DROP DEFAULT;
```

6. **새 시크릿 창**에서 결과물 주소를 연다.
7. 첫 화면이 로그인 화면인지, 로그인 없이 `/tasks` 를 열면 로그인 화면이 나오는지 확인한다.
8. 새 계정을 하나 만들어 **빈 다이어리**가 나오는지 확인한다(내 기록이 보이면 안 된다).

> 5단계를 미루면 안 된다. 임시 `DEFAULT` 가 남아 있으면 `user_id` 를 빠뜨린 INSERT 가 조용히 소유자에게 붙는다.
