## 2. 과제 6에서 이어 만든 내용

과제 6의 계획·할 일·실행 기록·돌아보기 구조와 기존 자료를 삭제하지 않고 같은 저장소·Vercel 프로젝트·Supabase PostgreSQL에서 이어 개발했다. 사용자가 직접 만든 소유자 계정에 기존 계획 2개·할 일 5개·돌아보기 1개를 귀속했다.

## 3. 인증 구현

- 아이디·비밀번호 가입과 로그인
- bcryptjs 3.0.3, cost 12 비밀번호 해시
- DB에 SHA-256 해시만 저장하는 7일 서버 세션
- 로그아웃과 비밀번호 변경 시 이전 세션 즉시 폐기
- 세션 사용자 ID를 기준으로 목록·검색·집계·조회·수정·삭제 차단
- 응답 DTO로 비밀번호·세션·소유자 내부 필드 제외
- 일간·주간·월간에서 할 일을 끌어 놓아 날짜 변경(소유자 조건 강제)
- 시작·종료 시각을 바탕으로 예상·실제 시간을 분 단위로 서버 자동 계산
- 공개 로그인·회원가입 선택 화면, 계정 찾기, 비밀번호 보기와 즉시 처리 상태
- 계획 연결 선택형 할 일과 시작일·마감일 날짜 범위
- DB·앱 새 연결은 `Asia/Seoul(+09:00)`로 표시하고 `timestamptz`의 실제 시점은 보존
- 진행 계획·계획 카드·연결 할 일에 같은 색을 적용해 계획 구분
- 날짜 입력의 클릭 범위를 보이는 박스로 제한하고 날짜 이동 성공 문구는 남기지 않음

가린 자동 결과는 `docs/과제7/evidence/auth-isolation-results.json`, 공개 PC 선택 화면은 `docs/과제7/evidence/T07-public-entry-pc.png`, PC 주간 플래너 화면은 `docs/과제7/evidence/T07-planner-drag-pc.png`에 있다.

**양방향 격리의 근거**: 2026-09-02 공개 배포 주소(`https://plan-do-see-diary.vercel.app`)에 일회성 계정 2개로 실행한 자동 검증 결과가 `auth-isolation-results.json` 의 `isolation` 배열에 두 방향(`owner-test → other-test`, `other-test → owner-test`)으로 기록되어 있다. 각 방향에서 읽기·수정·삭제·날짜 이동이 모두 404 이고, `target_unchanged: true`(거절이 상대 자료를 바꾸지 않음)와 `leaked_rows: 0`(목록 유출 없음)이 함께 남아 있다. Postman 화면 증거는 한 방향의 목록 격리(`T07-A22`)까지 촬영했고, 나머지 방향의 요청별 화면은 자동 검증 결과로 갈음한다.

## 5. 5일 실제 사용 결과

**답하려는 질문**: 하루에 계획한 시간과 실제로 쓴 시간의 차이를, 계획 규칙을 바꿔서 줄일 수 있는가?
**지표**: 하루 시간 오차율 (%) — `(그날 완료한 할 일의 실제 분 합 − 예상 분 합) ÷ 예상 분 합 × 100`, 소수 첫째 자리 반올림.

| 항목 | 값 |
|---|---|
| 실제 사용 날짜 5개 | 2026-08-29 · 08-30 · 08-31 · 09-01 · 09-02 (Asia/Seoul) |
| 1·2일차 규칙 | 하루 할 일 3건까지, 각 예상 시간 **60분 이하** |
| 규칙 변경 시각 | **2026-08-31 10:30:55** (`plan_revision.revised_at`) — 2일차 기록 뒤·3일차 기록(같은 날 15:30:23 생성) 앞 |
| 규칙 변경 이유 | 60분 제한 때문에 한 작업을 여러 할 일로 나눠야 해서 흐름이 끊겼다. 집중이 필요한 작업을 한 번에 계획하려고 상한을 올렸다 |
| 3~5일차 규칙 | 하루 할 일 3건까지, 각 예상 시간 **90분 이하** (바꾼 것은 상한 하나뿐) |
| 변경 **전** 평균 오차율 | **-30.1 %** (1일차 +33.3, 2일차 -93.5) |
| 변경 **후** 평균 오차율 | **-16.7 %** (3·4일차 0.0, 5일차 -50.0) |
| 5일 합계 | 예상 **81분** · 실제 **20분** · 차이 **-61분** · 평균 오차율 **-22.0 %** |
| 화면 값과 손 계산 대조 | **일치** — 돌아보기 화면(기간 2026.08.29–2026.09.04) 예상 81분·실제 20분·차이 -61분 = 손 계산. 증거 `T07-A17-five-day-totals-hand-check-pc.jpg` |
| 결과 한 줄 | 평균 오차율의 절댓값이 30.1% → 16.7% 로 줄었다 |

**해석에서 감추지 않은 것**: 개선의 대부분은 2일차 한 건(-93.5%)이 빠진 효과다. 2일차는 60분 상한에 맞추려고 62분으로 부풀려 잡았다가 4분에 끝난 날이라, 규칙 변경의 효과라기보다 그날의 어림 실패가 컸다. 하루 1건씩 5일뿐이므로 이 결론은 잠정이다.

**화면 기간이 9/4 까지인 이유**: 돌아보기 화면은 완료일이 아니라 **마감일**로 거른다. 5일치 할 일의 마감일이 8/31~9/4 에 걸쳐 있어 종료일을 9/4 로 잡아야 5건이 모두 집계된다. 또 이 화면에는 평균 오차율 항목이 없어(예상·실제·차이 3개), 평균은 손 계산으로만 구했다.

상세 입력표와 계산 규칙은 `docs/과제7/5일_사용기록.md`에 있다.

## 6. 남은 제한

- 로그인 시도 횟수 제한·계정 잠금·CAPTCHA가 없다.
- 비밀번호 찾기는 등록 정보 일치 방식이며 이메일 소유 확인·일회용 링크 발송은 없다.
- 관리자용 세션 강제 종료와 감사 로그가 없다.

핵심 제출 범위인 가입·로그인·즉시 세션 폐기·사용자별 자료 차단은 구현하고 배포 환경에서 검증했다.
