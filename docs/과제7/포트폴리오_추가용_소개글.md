# 포트폴리오 추가용 소개글 (과제 7)

## 한 줄 소개

계획-실행-회고(Plan-Do-See) 다이어리에 **직접 구현한 세션 인증**을 붙이고, **계층 구조로 접근 통제를 한곳에 모은** 웹 앱.

## 짧은 소개 (4~5줄)

이미 동작 중이던 다이어리에 아이디·비밀번호 로그인을 붙였습니다.
비밀번호는 bcrypt 로 되돌릴 수 없게 저장하고, 로그인 상태는 **서버 DB 에 보관한 불투명 세션 토큰**으로 관리해 로그아웃 즉시 이전 토큰이 무효가 되도록 했습니다.
접근 통제는 화면에서 숨기는 방식이 아니라 **모든 목록·집계가 지나는 조건 생성 함수 첫 줄에 소유자 조건을 고정**해, 조건을 빠뜨릴 자리 자체를 없앴습니다. 다른 사용자의 자료 요청은 존재를 감추는 404 로 거절됩니다.
"막았다"는 주장 대신 **성공 요청과 거절 요청을 나란히 놓은 기록**으로 검증했고, 아직 못 막은 것도 위험도와 함께 문서에 남겼습니다.

## 구조 — 왜 계층을 나눴는가

인증과 인가는 흩어지기 쉬운 관심사입니다. 라우트마다 소유자 조건을 적는 방식은 새 엔드포인트가 하나 늘 때마다 빠뜨릴 기회를 만듭니다.
그래서 계층을 고정하고 **"소유자 조건은 데이터 접근 계층에만 있다"** 를 규칙으로 삼았습니다.

```
app/**/page.tsx        View        화면. 서비스 결과를 그리기만 한다
app/api/**/route.ts    Controller  요청 해석 -> 세션 확인 -> 서비스 호출 -> DTO 응답
lib/service/           Service     업무 규칙과 트랜잭션 경계
lib/repository/        Repository  SQL. 모든 함수가 user_id 를 인자로 받는다
lib/domain/            Domain      순수 함수 (기간 계산, 집계 규칙, 검증 규칙)
lib/dto/               DTO         응답 필드 화이트리스트
```

이 구조가 면접에서 받는 질문에 그대로 답이 됩니다.

| 질문 | 답 |
|---|---|
| 남의 자료는 어디서 막히나요 | 데이터 접근 계층입니다. 목록·검색·집계가 모두 지나는 조건 함수 첫 줄에 소유자 조건이 있습니다 |
| 화면에서 숨긴 것 아닌가요 | View 는 그리기만 합니다. 차단은 SQL 에서 일어나고, 로그인 없는 직접 요청과 그 거절 응답을 기록으로 남겼습니다 |
| 비밀번호 해시가 샐 일은 없나요 | 응답은 DTO 화이트리스트만 통과합니다. `SELECT *` 가 새 컬럼을 자동으로 실어 나를 수 없습니다 |
| 규칙은 어떻게 검사했나요 | Domain 이 DB·HTTP 를 모르는 순수 함수라 단위 검사로 바로 확인합니다 |

## 이 프로젝트에서 보여 줄 수 있는 것

| 역량 | 근거 |
|---|---|
| **요구사항에서 기술 선택을 끌어내기** | "로그아웃 시 이전 토큰 무효화" 요구 하나가 JWT 기반 라이브러리(Auth.js Credentials)를 배제시켰고, 그 판단 근거를 문서로 남겼습니다 |
| **인증 구현** | bcrypt(작업 계수 12) 해시, 불투명 세션 토큰(DB 에는 SHA-256 만 저장), HttpOnly 쿠키, 만료·폐기 처리 |
| **수평 권한 상승 차단** | 소유자 조건을 데이터 접근 계층에 고정하고, 요청의 URL·헤더·본문에서는 사용자 ID 를 읽지 않음 |
| **거절이 자료를 바꾸지 않게 설계** | 소유자 조건을 UPDATE/DELETE 의 WHERE 에 함께 두어, 권한 검사와 변경 사이에 순서를 틀릴 자리를 없앰 |
| **호환을 깨지 않는 스키마 변경** | 운영 중인 앱과 DB 를 공유한 채로 소유자 컬럼을 추가. NULL 허용 -> 백필 -> 임시 DEFAULT -> NOT NULL 4단계로 무중단 처리 |
| **입력 규칙을 한 곳에 모으기** | 아이디·닉네임·비밀번호 규칙을 순수 함수 한 파일에 두고, 화면 안내와 별개로 서버에서 반드시 재검사 |
| **증거 기반 검증** | 다섯 가지 확인 항목을 각각 성공·거절 요청 쌍으로 기록. 거절 전후 상대 계정 자료 건수 대조 |
| **한계를 정직하게 문서화** | 무차별 대입·비밀번호 재설정·2FA·보안 로그·CSRF 토큰 미구현을 위험도와 함께 명시 |
| **자료로 자기 행동 바꾸기** | 5일간 실제 사용하며 하루 시간 오차율을 측정하고, 3일차 전 계획 규칙을 하나만 바꿔 전후를 같은 지표로 비교 |

## 기술 스택

Next.js 16 (App Router) · TypeScript · PostgreSQL (원시 SQL) · bcryptjs · Vercel
